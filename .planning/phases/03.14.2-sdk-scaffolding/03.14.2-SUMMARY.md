## Deviations from Plan

### Auto-fixed Issues

- **Latent `os.environ.get` NameError in cli.py:103/113/123** — the
  original 03.14.0 ontology parser had a latent bug: the `--l5-db-path`
  argument default used `os.environ.get(...)` directly, but `os` was
  never imported at module level (the existing `os_environ_or` helper
  had a function-local `import os` which only fires when called).
  This bug had never been surfaced because nobody had smoke-tested
  `eaasp-ecosystem ontology derive` end-to-end. 03.14.2 fixed all
  three call sites by routing through `os_environ_or(name, "")` (the
  helper is defined at the bottom of the file and lazy-imports `os`).
- **Files modified**: `tools/eaasp-ecosystem/src/eaasp_ecosystem/cli.py`
  (3 lines changed at line 116/126/135 in the ontology parser block).
- **Commit**: included in `ced94f33`.

- **Pyright `data possibly unbound` warnings in ecosystem_cmd.py** —
  the Click subcommand callbacks use a `try / except` pattern that
  Pyright flags as "data" being possibly unbound at the post-try call
  site. Resolved by initializing `data: dict = {}` inside the
  `with _build_client_from_ctx(ctx) as client:` block (6 sites).
- **Files modified**: `sdk/python/src/eaasp/cli/ecosystem_cmd.py` (6
  annotations added).
- **Commit**: included in `de70d199`.

## Decisions

- **D-42 thin client, no business logic re-implemented** — every
  method in `EaaspEcosystemClient` is a single HTTP call to an
  existing FastAPI endpoint. The SDK is a typed HTTP wrapper.
- **No new `eaasp_sdk/` package** — the SDK extends the existing
  `eaasp` package alongside `skill_registry.py` and
  `platform_client.py`. The `.planning/PROJECT.md:104` reference to
  `eaasp_sdk/` is stale; documented in the project plan as "extend
  existing `eaasp` package".
- **All CLI subcommands go through HTTP** — no `--offline` dual-mode
  for marketplace reads (per the v3.14.0 round-1 audit; an in-process
  CLI would create a guard-bypass class).
- **Click `envvar=EAASP_ECOSYSTEM_API_KEY` parameter** — Click
  auto-resolves the env var to the `--api-key` flag default; matches
  the v3.13.2 L5 retrospect trace CLI's env-var convention.
- **`httpx.Client(trust_env=False)`** — skips the macOS Clash proxy
  per the project-wide `feedback_env_var_conventions` gotcha.
