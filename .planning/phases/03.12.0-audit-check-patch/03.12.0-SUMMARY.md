## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Migration logic missed two edge cases caught by new tests**
- **Found during:** Task 2 (test commit `4a73827b`).
- **Issue:** Two latent bugs in `db.py` migration:
  1. The inline `SCHEMA` created `idx_governance_decisions_stage` on the
     `stage` column. Pre-v3.11.2 DBs (no `stage` column) failed with
     `no such column: stage` when `init_db` ran the SCHEMA via
     `executescript`.
  2. The migration's row-copy `INSERT INTO new SELECT * FROM legacy`
     assumed identical column lists. v3.11.0 / v3.11.1 legacy tables
     lack `stage`; `SELECT *` returns 9 columns but the new schema has
     10, raising `Incorrect number of bindings`.
- **Fix:**
  1. Move indexes OUT of inline `SCHEMA` into
     `_create_governance_decisions_indexes(path)`, invoked from
     `init_db` AFTER the conditional `stage` column add.
  2. Probe `PRAGMA table_info` for the legacy column list, then
     `INSERT INTO new (col1, col2, ...) SELECT col1, col2, ... FROM legacy`
     projects only the columns the legacy row carries.
- **Files modified:** `tools/eaasp-l3-governance/src/eaasp_l3_governance/db.py`
- **Commit:** `4a73827b` (test commit)

## Decisions

- **Idempotent migration via table-rebuild**: SQLite does not support
  `ALTER TABLE ... DROP CONSTRAINT` or `ALTER TABLE ... ALTER COLUMN`,
  so the migration uses the rename + create + copy + drop pattern
  inside `BEGIN IMMEDIATE`. Existing rows preserved via `PRAGMA table_info`
  column-list projection (handles v3.11.0 / v3.11.1 / v3.11.2 / v3.11.3
  legacy shapes).
- **`approve_pause` row for paused-state evidence**: The state machine
  appends a dedicated `approve_pause` ledger row carrying
  `DECISION_AWAIT_HUMAN` after the upstream `approve` policy verdict row.
  Distinct `decision_id` PK (`<request_id>_approve_pause`) preserves the
  append-only invariant. The in-memory `records` list mirrors the
  ledger shape.
- **Index creation moved out of inline `SCHEMA`**: Indexes on
  `governance_decisions` are created AFTER the conditional `stage`
  column add so legacy DBs without the column don't fail the
  `CREATE INDEX ... WHERE stage IS NOT NULL` statement.
