# Phase 03.9.0 Plan — Route catalog and public allowlist

## Objective

Establish a public, typed source of truth for every `grid-server` HTTP route before enforcement is expanded. Each entry records method, canonical path, and either `Public` or `Requires(Action)`.

## Locked context

- Cover all routes assembled by `router::build_router`, including top-level health and WebSocket endpoints and every `/api/v1` route.
- Public allowlist is compile-time data and contains only `/api/health`, `/api/health/live`, and `/api/v1/auth/login`.
- Catalog remains data-only in this phase; Phase 03.9.1 consumes it for full RBAC wiring.
- No dependency or schema changes.

## Tasks

### Task 1 (TDD RED): catalog completeness contract

Create a targeted integration test that expects a public `rbac::catalog` API, validates the exact public allowlist, rejects duplicate `(method, path)` entries, and checks representative top-level, nested, merged, and multi-method routes. The test must fail before implementation.

### Task 2 (TDD GREEN): typed route catalog

Add `crates/grid-server/src/rbac/catalog.rs` and module exports with:

- `RouteCatalogEntry { method, path, route_kind }`
- `RouteKind::{Public, Requires(Action)}`
- `PUBLIC_ROUTE_ALLOWLIST`
- `build_catalog()` / `route_catalog()` as public consumers

Populate every production HTTP method/path pair assembled by `build_router`; canonicalize `/api/v1` and `/scheduler` prefixes in catalog paths.

### Task 3: targeted verification and independent review

Run:

- catalog integration test
- `cargo check -p grid-server`
- catalog consistency checks for duplicates and allowlist symmetry

Perform a separate review pass for omissions, accidental public exposure, route-prefix mistakes, and future auditor usability. Fix confirmed findings before phase summary.

## Success criteria

- CAT-01: complete typed catalog exists and corresponds to the production router surface.
- CAT-02: public allowlist is explicit and exact.
- CAT-04: catalog API is public to integration tests and the later auditor.
- No behavior change to any AuthMode in this phase.
