## Deviations from Plan

### Auto-fixed Issues (security review round-1 @ `88b1d405` → `88bff405`)

- **Found-during**: v3.7.3 v3.9 audit round-1 surfaced 3 issues:
  1. `X-Tenant-Id` header was trusted by the ontology service (tenant-binding bypass).
  2. `?tenant_id=` query param was trusted (same bypass vector).
  3. `_assert_same_tenant` returned silently when `row_tenant` was `None` (dead fail-open code path).
- **Issue**: cross-tenant data leakage; the L2 / L3 / L4 stores don't natively
  support per-row tenant filtering, so the service previously had to
  trust client-supplied tenant identifiers.
- **Fix**: locked the contract so the caller's tenant is **always** resolved
  from the authenticated principal (server-side via `_require_principal`).
  The ontology service treats any `tenant_id=None` or `""` as a security
  violation (raises `CrossTenantForbidden`). 5 new regression tests
  locked the behavior in `test_ecosystem_backend.py`.
- **Files modified**: `tools/eaasp-ecosystem/src/eaasp_ecosystem/ontology.py`
  (the `OntologyService._assert_same_tenant` fail-closed branch +
  `_resolve_tenant` empty-tenant rejection), `test_ecosystem_backend.py`
  (+5 tests).
- **Commit**: `88bff405 fix(03.14.0): round-1 security review — auth + cross-tenant filter + fail-closed`.

## Decisions

- **Stable node_id from `(layer, key, tenant_id)` SHA-256 hash** — ensures
  determinism across re-runs (idempotent) and prevents cross-tenant
  node collisions.
- **Synthetic "root" node always present** — gives the marketplace / SDK
  a stable entry point for `list_taxonomy()` without needing to special-case
  the empty-graph case.
- **Cross-tenant fail-closed at every access** — even when `row_tenant` is
  `None` (no row available to compare), the service raises
  `CrossTenantForbidden` rather than silently passing (per round-1 audit
  fix).
- **D-40 "派生不复制" honored** — `OntologyService` is a pure
  read-only projection; no new tables, no new columns, no new event
  types in the L2 / L3 / L4 / L5 stores.
