## 需求交叉核验

### AUTH — 5/5

- **AUTH-01**：JWT 含 `sub`、`tenant_id`、`role`、`iat`、`exp`，另含注销所需 `jti`。
- **AUTH-02**：`POST /api/v1/auth/refresh` 验证旧 JWT，并从 `UserStore` 重新读取角色与租户后签发新 JWT。
- **AUTH-03**：`POST /api/v1/auth/logout` 将 `jti` 加入黑名单；保护中间件在每个 Full-mode 请求中查询黑名单。
- **AUTH-04**：未知用户和错误密码共享同一个安全 401 body；过期、篡改和缺失声明的 JWT 均拒绝。
- **AUTH-05**：HS256；`GRID_JWT_SECRET` 在 Full mode 下严格校验，最少 32 字节。

### RBAC — 4/4

- Role × Action 矩阵通过 JWT-aware `require_action_middleware` 执行。
- Viewer/User/Admin/Owner 的代表性路径和 Owner 超级用户语义有密闭测试。
- v3.8 的承诺是核心中间件与代表性路由验证；全 route catalog 接入按照 03.8.2 的已批准边界延期至 v3.9+。

### TENANT — 3/3

- Full-mode claims 转换为 `TenantContext::for_multi_user`。
- None/ApiKey 路径继续使用原单用户语义，`test_auth_modes` 8/8 通过。
- 跨租户资源访问返回 `tenant_mismatch`，不会序列化底层数据。

### SESSION — 3/3

- `SessionStore` 暴露 tenant-scoped get/list 接口。
- `TenantSessionResult::{Ok,TenantMismatch,NotFound}` 保留安全区分。
- 两用户、两租户的并发隔离在密闭集成测试中覆盖。

### AUDIT — 2/2

- Audit rows 携带 `tenant_id`、`user_id`、`role`。
- 普通查询始终按 caller tenant 过滤；只有 Owner + `cross_tenant=true` 可越租户，并写 SECURITY row。
- AUDIT-02 IDOR hotfix `4b6a3539` 有回归测试。

### TEST — 6/6

- 两租户并发隔离、角色越权、JWT 过期、缺失声明均有测试。
- 五场景 UAT 记录在 `docs/status/PRODUCTION_USABILITY_2026-07-24.md`。
- 03.8.3 针对性回归为 **119/119 PASS**：33 v3.8 hermetic + 44 auth + 3 tenant + 39 audit。

### DOC — 3/3

- `docs/cli/USER_GUIDE.md` §11 完成。
- 运维变量采用代码中的真实名字：`GRID_AUTH_MODE`、`GRID_JWT_SECRET`、`GRID_TOKEN_TTL_SECS`、`GRID_USERS_JSON`。
- 日期化 walkthrough 完成，明确区分密闭 PASS 与缺少 API key 的 live LLM walkthrough。
